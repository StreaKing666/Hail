# Hail Enhanced .14 — KSU, замена оригинального пакета

Вложен подписанный APK Enhanced .14 с packageName `com.aistra.hail`, без изменения его байтов и подписи. Это вариант оригинального пакета, а не клон `com.aistra.hail.enhanced`.

ID модуля: `Hail-System-PrivApp`. APK: `/system/priv-app/Hail/Hail.apk`.
XML: `/system/etc/permissions/privapp-permissions-com.aistra.hail.xml`.
Существующий модуль с этим ID обновляется через менеджер, вместо создания второго модуля. Иные активные модули с известным путём APK Hail или XML для этого пакета отклоняются установщиком. Неизвестные инжекторы с переименованным APK без allowlist могут не распознаться.

## Установка

1. Сохраните резервную копию Hail во внешнюю папку. Не удаляйте приложение и не очищайте его данные для установки этого ZIP.
2. Нужен работающий KernelSU/ReSukiSU и механизм монтирования `system`. Если имеющийся NoMount выполняет эту задачу, второй метамодуль не устанавливайте. Работу с конкретной версией NoMount на телефоне здесь не проверяли.
3. Установите ZIP в менеджере root и перезагрузите телефон. Если есть другой модуль для `com.aistra.hail` с иным ID, сначала отключите его. Recovery-установка не предусмотрена.
4. Нажмите «Действие»/Action у модуля. Проверьте `Active APK matches module: YES`, видимость APK и XML, системную классификацию, флаг PRIVILEGED и `granted=true` у CHANGE_COMPONENT_ENABLED_STATE и FORCE_STOP_PACKAGES.
5. Откройте Hail и выберите «Системное приложение — Отключить» либо «Системное приложение — Принудительно остановить». Проверьте на одном некритичном приложении. Принудительная остановка не является обратимой заморозкой: для запуска приложение требуется открыть.

## Подпись и /data/app

Одинаковый packageName не делает подписи одинаковыми. Enhanced подписан своим сертификатом; сертификат upstream не перенесён. Модуль не отключает системную проверку подписей и не настраивает патчи Lucky Patcher. Их совместимость и влияние на регистрацию пакета на этом устройстве не проверены.

Если оригинал или его обновление находится в `/data/app`, Android может оставить его активным либо отклонить APK модуля из-за подписи. При `Active APK matches module: NO` замена ещё не подтверждена. Сохраните вывод Action для диагностики; установщик не удаляет мешающий APK автоматически. Не очищайте данные ради устранения этой ситуации.

XML содержит четыре запрашиваемых разрешения приложения. На Android 16 MANAGE_APP_OPS_MODES не имеет privileged-флага, поэтому одно помещение в priv-app его не выдаёт. Модуль не назначает Device Owner и не выдаёт разрешения Shizuku/Dhizuku. Отсутствие MANAGE_APP_OPS_MODES само по себе не означает отсутствие прав на отключение и принудительную остановку.

## Данные и откат

Нет команд удаления/очистки пакета, записи в его `/data/user*`, загрузочных сервисов, правок SELinux или физических файлов прошивки. Это не является гарантией сохранности данных при любой реакции PackageManager на смену подписи. Реальная замена оригинала, миграция его данных, перезагрузка и откат на устройстве — NOT_RUN.

Для отката отключите этот модуль в root-менеджере и перезагрузите телефон; при необходимости верните прежний ZIP модуля. Внешняя резервная копия нужна до начала. Не устанавливайте старую версию Hail поверх новых данных без проверенной процедуры восстановления.

## Аудит и исходники

APP_AUDIT.md содержит повторную проверку вложенного APK и оставшиеся ограничения. Полный lint сохраняет ошибки неполных переводов; проверки на устройстве не выполнены. Ручные длительные операции выполняются в фоне, состояние после команды наблюдается с ограниченным ожиданием без повторной команды.

Сборка из исходников обёртки:
`python3 tools/build.py --variant original --apk /path/to/Hail-original.apk --output module.zip`
Python 3 + cryptography. Вариант original проверяет пакет и закреплённый сертификат Enhanced, отклоняя клон, постороннюю подпись и повреждение. APK не перепаковывается.

Источники требований: https://kernelsu.org/guide/module.html ; https://kernelsu.org/guide/metamodule.html ; https://source.android.com/docs/core/permissions/perms-allowlist .
