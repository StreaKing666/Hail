# Hail Enhanced Privileged 1.0.0 / Enhanced .12
Неофициальный systemless-модуль на основе Hail Universal Privileged 2.1.0 (+SWAG+).
Вложен подписанный Enhanced .12; упаковка не изменяет и не переподписывает APK. Модуль остаётся тестовым до проверки на устройстве.

## Установка
1. Экспортируйте данные Enhanced во внешнюю папку.
2. Для KernelSU/ReSukiSU нужен один работающий метамодуль монтирования system. Если NoMount уже работает, второй не добавляйте. Magisk отдельный метамодуль не требует.
3. Установите ZIP через root-менеджер, затем перезагрузитесь. Recovery не поддерживается.
4. Выполните Action в карточке модуля. Проверьте видимость APK/XML, системную классификацию, PRIVILEGED и granted=true у нужных разрешений.
5. В Enhanced выберите «Системное приложение - Отключить» либо «Системное приложение - Принудительно остановить». Проверьте заморозку/разморозку некритичного приложения.

Модуль не назначает Device Owner и не выдаёт доступ Shizuku/Dhizuku. XML не гарантирует выдачу каждого разрешения на любой прошивке; Action показывает фактический результат.

## Совместимость
- ID модуля: Hail-Enhanced-PrivApp; оригинальный Hail-System-PrivApp не заменяется.
- Пакет: com.aistra.hail.enhanced; оригинальный com.aistra.hail не заменяется.
- APK: /system/priv-app/HailEnhanced/HailEnhanced.apk.
- XML: /system/etc/permissions/privapp-permissions-com.aistra.hail.enhanced.xml.
- Инсталлятор не удаляет приложение, данные или другие модули.
- Установленная копия Enhanced в /data/app может иметь приоритет как пользовательское обновление. Нужна совпадающая подпись. Сертификат уже установленной копии на телефоне инсталлятор не проверяет.
- Проверяются SHA256 вложенных APK и XML; сборщик проверяет подпись и сертификат APK.
- Известные дубли Enhanced в активных и ожидающих установки модулях блокируются. Любой произвольно переименованный APK без XML такая проверка распознать не может.
- Оба Hail способны управлять одними приложениями: противоположная автоматизация может конфликтовать.
- Общая схема ссылок hail:// может вызвать выбор обработчика Android.
- Автоматического переноса настроек из оригинала нет.

## Удаление и обновление
Перед отключением/удалением разморозьте приложения и экспортируйте данные. Удалите модуль через root-менеджер и перезагрузитесь.
Скрипта очистки данных нет. Не рассчитывайте на сохранность единственной локальной копии: поведение системного пакета и его пользовательского обновления после удаления модуля зависит от PackageManager.
Обычное обновление APK Enhanced возможно по правилам Android при совпадении подписи. Более новая копия /data/app может иметь приоритет над вложенной .12.

## Проверки и ограничения
На реальном устройстве этот Enhanced-модуль не устанавливался. Результаты тестирования прежнего оригинального модуля на него не переносятся.
Нет WebUI, новых Zygisk/LSPosed-компонентов, boot-сервисов, правок SELinux или физической записи в /system. Возможности самого APK остаются прежними.
Полный lint остаётся незакрытым из-за неполных переводов. Замечания WrongConstant и NewApi исправлены. Проверка автоматизации, восстановления и интерфейса на устройстве не завершена. Текущий отчёт — docs/RELIABILITY_REPORT_2026-11-05.md в исходниках приложения; APP_AUDIT.md описывает прежнюю .11.
